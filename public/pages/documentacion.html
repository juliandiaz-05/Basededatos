Documentación del Proyecto

Justificación, objetivos, análisis del problema, requisitos y modelado del sistema.

Introducción

La industria cinematográfica es un universo en el que convergen creatividad, técnica, logística y economía. Cada película es el resultado de un proceso complejo que involucra cientos de personas, recursos materiales y decisiones estratégicas que deben coordinarse con precisión. El presente proyecto propone un Sistema de Control de Producción Cinematográfica, concebido como una plataforma integral capaz de supervisar todas las etapas de un proyecto audiovisual, desde la preproducción hasta la distribución, con un nivel de detalle que garantice calidad, eficiencia y transparencia.

La magnitud del proyecto se refleja en la diversidad de elementos que deben gestionarse de manera simultánea: guiones, cronogramas, presupuestos, locaciones, actores, técnicos, equipos de filmación y procesos de postproducción. La plataforma consolida toda esta información en tiempo real, para que productores, directores y equipos técnicos accedan de inmediato a los datos necesarios para tomar decisiones críticas.

Objetivos

Objetivo general

Diseñar e implementar un sistema de información web que permita controlar la producción cinematográfica, integrando la gestión de producciones, personal, locaciones, escenas, cronogramas de rodaje y alertas sobre una base de datos MySQL, garantizando trazabilidad y transparencia en la asignación de recursos.

Objetivos específicos

  • Modelar la base de datos relacional del sistema con claves primarias, foráneas e integridad referencial.
  • Desarrollar una interfaz web interactiva y de fácil uso para los distintos actores del proceso.
  • Permitir el registro, consulta, actualización y eliminación de producciones, personal, locaciones, escenas, planes de rodaje y alertas (CRUD).
  • Implementar reglas de negocio: cancelación y reprogramación de rodajes por clima adverso, con generación automática de alertas.
  • Generar reportes y estadísticas (panel de control) que permitan detectar desviaciones presupuestarias y del cronograma.
  • Garantizar seguridad, respaldo y rendimiento de la información mediante buenas prácticas y requisitos no funcionales.

Justificación

Actualmente las producciones cinematográficas se gestionan con hojas de cálculo y documentos dispersos, lo que genera pérdida de información, errores humanos, retrasos en el cronograma y sobrecostos difíciles de detectar a tiempo. La inexistencia de una fuente única y confiable de datos impide anticipar problemas como condiciones climáticas adversas o desviaciones del presupuesto.

El sistema se justifica porque: (1) centraliza la información de todas las áreas de una producción en tiempo real; (2) automatiza reglas de negocio críticas como la cancelación de rodajes por clima y las alertas presupuestarias; (3) facilita la interoperabilidad entre productores, directores, técnicos y autoridades culturales; (4) garantiza la transparencia en la asignación de recursos; y (5) es escalable para gestionar múltiples producciones de manera simultánea, incluso en contextos de coproducción internacional.

Análisis del problema

Contexto y antecedentes

En la industria del cine convergen múltiples actores con necesidades específicas: los productores supervisan cronogramas y presupuestos; los directores coordinan escenas y locaciones; los técnicos registran procesos de filmación; y las autoridades culturales verifican el cumplimiento de normativas. La gestión se realiza en su mayoría con herramientas genéricas que no reflejan las particularidades de un rodaje.

Descripción del problema

  • Desinformación: no existe una vista consolidada del estado real de cada producción.
  • Desviaciones tardías: el sobrecosto del presupuesto se detecta cuando ya es difícil corregirlo.
  • Impacto del clima: una escena cancelada por clima afecta el cronograma sin que el sistema sugiera alternativas.
  • Falta de trazabilidad: las decisiones no quedan registradas ni justificadas para auditorías.
  • Datos sensibles: la información es valiosa y su manipulación indebida afecta la reputación de las empresas.
  • Dificultad de escalar: los métodos manuales no soportan miles de registros ni múltiples producciones simultáneas.

Solución propuesta

Una aplicación web conectada a una base de datos MySQL que unifica la información, automatiza alertas, genera reportes, protege los datos y escala según la demanda, respetando además la dimensión artística y creativa del cine.

Requisitos no funcionales

🔐 Seguridad

Acceso autenticado, protección contra accesos no autorizados, manipulación indebida o pérdida accidental; confidencialidad e integridad de los datos.

⚡ Rendimiento

Respuesta ágil de la interfaz y consultas optimizadas con índices, capaz de gestionar miles de registros por producción.

🗺 Disponibilidad

Servidor disponible en la red local; mecanismos de respaldo (backup) y recuperación de la base de datos.

🛡 Escalabilidad

Gestión simultánea de múltiples producciones y crecimiento sin perder rendimiento ni disponibilidad.

👥 Usabilidad

Interfaz clara y accesible para usuarios con distintos niveles de alfabetización digital.

🔗 Interoperabilidad

API REST que permite la integración con otros sistemas y protocolos heterogéneos del sector.

🌍 Cumplimiento normativo

Adaptación a normativas internacionales de protección de datos y requisitos de organismos culturales.

📝 Mantenibilidad

Código organizado y documentado para facilitar su evolución y auditoría.

Actores del sistema

🎬 Productores

Supervisan cronogramas y presupuestos, aprueban decisiones y verifican la asignación de recursos.

🎯 Directores

Coordinan escenas y locaciones, dirigen al equipo y toman decisiones creativas y logísticas.

🔧 Técnicos

Registran procesos de filmación, resultados de pruebas y soporte de equipos de sonido, cámara y edición.

🏥 Autoridades culturales

Verifican el cumplimiento de normativas, estándares y requisitos regulatorios de cada país.

🇮 Proveedores y comunidades

Dependen de la eficiencia del sistema para garantizar su trabajo y exigir transparencia.

Modelo de datos (Base de datos control_cinematografico)

El modelo relacional está compuesto por 6 tablas con claves primarias, foráneas e integridad referencial (borrado en cascada de escenas y alertas, y SET NULL en la locación), más una vista de resumen.

TablaCamposRelaciones
Produccionid_produccion, titulo, estado, presupuesto_total, fecha_inicio, fecha_fin_estimada1:N con Escena y Alerta
Personalid_personal, nombre, rol, email, telefono, pais_origenEquipo de trabajo
Locacionid_locacion, nombre, direccion, pais, costo_diario1:N con Escena (SET NULL)
Escenaid_escena, id_produccion, id_locacion, numero_escena, descripcion, tipo_ambiente, clima_requeridoN:1 con Produccion y Locacion; 1:N con Plan_Rodaje
Plan_Rodajeid_plan, id_escena, fecha_rodaje, estado_rodajeN:1 con Escena (cascada)
Alertaid_alerta, id_produccion, tipo, mensaje, fecha_registroN:1 con Produccion (cascada)

💡 Se usa ALTER TABLE para adicionar la columna telefono a Personal y un índice idx_tipo_ambiente sobre Escena, y una vista v_resumen_produccion que agrupa indicadores de cada producción.

Glosario de términos

Base de datos: conjunto organizado de datos estructurados, almacenados electrónicamente.
CREATE DATABASE: comando SQL para crear una nueva base de datos.
CREATE TABLE: comando SQL para crear una nueva tabla.
PRIMARY KEY: columna o conjunto de columnas que identifican de forma única cada fila.
FOREIGN KEY: columna que establece una relación con la clave primaria de otra tabla.
AUTO_INCREMENT: atributo que incrementa automáticamente el valor de una columna numérica.
NOT NULL: restricción que impide valores nulos.
DEFAULT: valor asignado automáticamente si no se proporciona uno.
Vista (View): consulta guardada que actúa como una tabla virtual.
Índice (Index): estructura que mejora la velocidad de búsqueda.
Rodaje: proceso de filmación de las escenas de una producción.
Preproducción: etapa de planeación, casting y preparación de locaciones.
Postproducción: edición, sonido y efectos tras el rodaje.
